INTRODUCTION                                                   *PlatformIO*

A plugin for wrapping PlatformIO commands with user-friendly Neovim commands.

==============================================================================

USAGE                                                    *platformio-usage*

                                   *:Pioinit*
:Pioinit                 Open Neovim in a fresh directory, run `:Pioinit`, and
                         follow the prompt to initialize a project. A telescope
                         picker will appear for selecting the board, and then
                         another for choosing the framework. Press enter to
                         complete the initialization.

                                   *:Piorun*
:Piorun [arg]            This command builds and uploads the code. Optional
                         arguments: build, upload, uploadfs, clean. If no
                         argument is provided, it defaults to build and
                         upload.
                         Examples:
                            `:Piorun`
                            `:Piorun build`
                            `:Piorun upload`
                            `:Piorun uploadfs`
                            `:Piorun clean`

                                   *:Piocmd*
:Piocmd[f|h] [cmd]       Run PlatformIO commands either in float or horizontal direction.
                         Example: `:Piocmdf device list`.
                         The command argument is optional. If not provided, it
                         opens a floating toggleterm in the project root where
                         you can execute commands. Note: `pio` keyword is not
                         required in the command.
                         Examples:
                            `:Piocmdh`
                            `:Piocmdh run -e uno -t upload`
                            `:Piocmdf device list`
                            `:Piocmdf boards arduinouno --json-output`

                                   *:Piolib*
:Piolib [libname]       Install a library by providing a keyword for search. A
                         telescope picker will show available libraries. Pick
                         one and press enter to install.
                         Examples:
                            `:Piolib arduino json`
                            `:Piolib keyboard`

                                   *:Piomon*
:Piomon [baud] [port]   Open a serial monitor. Specify a baud rate and,
                         optionally, a port. If not provided, it uses the
                         default baud rate (9600) or the one specified in
                         platformio.ini, and auto-detects the port.
                         Examples:
                            `:Piomon`
                            `:Piomon 115200`
                            `:Piomon 115200 /dev/ttyUSB0`

                                   *:Piolsserial*
:Piolsserial		List out all the serial devices connected with their
			description

                                   *:PioLSP*
:PioLSP			Generates LSP config and restart the LSP connection.
			It is based on your configuration. If `ccls` is
			picked it generates the `.ccls` file and if `clangd`
			is picked it generates `compile_commands.json` file.
			This command can be used in a fresh cloned project
			which doesnt have LSP configs. 

                                   *:Piodebug*
:Piodebug		 Starts the default PlatformIO debugger with gdb

                                   *:PioTermList*
:PioTermList             Lists open PIO terminals (CLI and monitor) and lets
                         you pick one to switch to. Not bound to any key by
                         default; bind it yourself or add it to
                         `menu_bindings` (see |platformio-configuration|).

CONFIGURATION                                        *platformio-configuration*

The plugin exposes a few configuration options that can be set in your
`setup()` call.

lsp                                                              *platformio-lsp*
    Which language server the generated project config should target.
    Allowed values: `ccls` (default) or `clangd`. See |platformio-clangd_source|
    below when using `clangd`.

clangd_source                                          *platformio-clangd_source*
    PlatformIO CLI officially only supports generating LSP configuration for
    CCLS, since it creates a `.ccls` file when you use the `--ide=vim` flag.
    However, it does not generate any configuration for clangd. To get
    clangd working, we need a `compile_commands.json` file, which can be produced 
    in two different ways:

    - `ccls`
          This option uses the `.ccls` file generated by the PlatformIO
          CLI and creates a `compile_commands.json` based on it. It does
          this by extracting the compiler, `-I`, and `-D` flags from the
          `.ccls` file, which are essential for autocompletion.

    - `compiledb`
          This option generates the `compile_commands.json` file by running
          `pio run -t compiledb`.

    Initially, the plugin relied only on `compiledb` to generate configuration
    for `clangd`, but there were many reports—especially from users of the
    Espressif/ESP32 platform—about `clangd` throwing strange errors. This
    happens because the `compiledb` target produces a `compile_commands.json`
    intended for building the project, not for consumption by `clangd`, which
    often results in messy or incompatible entries.
    
    This led to the idea of generating a clean `compile_commands.json` using
    the `.ccls` file, picking only the `-I` and `-D` flags and ignoring
    everything else. This usually provides much better autocompletion, though
    it is still not perfect in all cases.
    
    Try both methods and choose the one that works best for your setup. I am
    also open to suggestions to further improve clangd support.

picker_backend                                            *platformio-picker*
    The plugin uses a picker abstraction for interactive selection flows used
    by `:Pioinit` and `:Piolib`. This keeps command logic separate from UI so
    different picker UIs can be used without changing command behavior.

    Set this in `setup()`:
      >lua
        require('platformio').setup({
          picker_backend = 'auto',
        })
      <

    Allowed values:
    - `auto`
          Default. Tries backends in this order, using the first one that is
          installed: `telescope`, then `snacks`, then `mini_pick`, then
          `ui_select`. `ui_select` is always available since it only needs
          Neovim's built-in `vim.ui.select`, so `auto` never fails to find
          a backend.

    - `telescope`
          Force the Telescope picker backend (requires telescope.nvim).

    - `snacks`
          Force the Snacks picker backend (requires folke/snacks.nvim with
          its `picker` module enabled).

    - `mini_pick`
          Force the mini.pick backend (requires nvim-mini/mini.pick).

    - `ui_select`
          Force `vim.ui.select` backend. This works with Neovim built-in
          `vim.ui.select` or any plugin that overrides it (for example,
          telescope-ui-select, dressing.nvim, snacks' `ui_select` option,
          mini.pick's `MiniPick.ui_select`, etc.).

    Unlike `auto`, explicitly requesting `telescope`, `snacks`, `mini_pick`,
    or `ui_select` does NOT fall back to another backend if the requested
    one isn't installed—it reports an error and the picker does not open.

menu_key                                                    *platformio-menu_key*
    Key prefix that opens the PlatformIO which-key menu (requires
    folke/which-key.nvim). Unset (`nil`) by default, which disables the menu
    entirely. Example: `menu_key = '<leader>\\'`.

menu_name                                                  *platformio-menu_name*
    Display name for the top-level menu group shown by which-key.
    Default: `'PlatformIO'`.

menu_bindings                                          *platformio-menu_bindings*
    Table describing the which-key menu tree: nested `menu` nodes (with
    `desc`, `shortcut`, `items`) and `item` nodes (with `desc`, `shortcut`,
    `command`). See the README for the full default table, which you can
    copy and edit. Note that a partial table does not selectively override
    individual default entries — provide the whole tree if you customize it.

debug                                                          *platformio-debug*
    When `true`, echoes extra diagnostic info (terminal name, window/buffer
    ids, job id) each time a PIO terminal opens. Default: `false`.
